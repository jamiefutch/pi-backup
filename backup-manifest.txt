# pi-backup manifest: the single source of truth for what is backed up and restored.
# Read by backup-pi.sh, restore-pi.sh, backup-pi.ps1 and restore-pi.ps1.
# LF line endings only (enforced by .gitattributes). Paths use "/" on every platform.
# Paths on the left are relative to PI_ROOT (default ~/.pi); the right side is relative to the backup.
#
#   section|<title>                      starts a numbered step in the script output
#   file|<pi path>|<backup path>         one file; missing files are skipped with a warning
#   dir|<pi path>|<backup path>          a whole directory; replaced on restore
#   dir-each|<pi path>|<backup path>     each sub-directory is backed up / replaced separately
#   local-ext|<name>                     source tree under LOCAL_EXT_ROOT (node_modules, dist, build, .git, coverage, *.log excluded)
#   npm|<pi path>|<backup path>          package.json and lockfiles only (max depth 3), never node_modules
#   recent|<pi path>|<backup path>|<n>   the n newest sub-directories whose name starts with "20" (timestamps)
#
# Keep README.md "What Gets Backed Up" in sync; tests/sh/manifest.test.sh checks it.
